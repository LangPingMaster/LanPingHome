01｜開發目標與交付成果正式要求

用 RV32I assembly 完成兩個 ABI 相容的函式。Runtime 直接呼叫入口，正常 ret 後檢查原輸入記憶體。兩者皆為 void；印出答案或回傳某個位址都不能取代修改原緩衝區。

檔案入口與參數完成結果
asm-prog-assignment/merge.Sarray_sort；a0=array、a1=size原陣列依 signed int32_t 升序；必須 Merge Sort
asm-prog-assignment/sudoku.Ssudoku_solver；a0=board原棋盤完成；原始線索不變
void array_sort(int32_t *array, uint32_t size);
void sudoku_solver(int32_t *board);
  • 不用報告，不用 Moodle 壓縮檔；正式提交走 Classroom50。
  • 檔名、路徑、大小寫完全一致；一般檔案，不能是 symbolic link；每檔 ≤262,144 bytes，無 NUL byte。
  • 兩檔獨立組譯、連結、執行，不能互相供應 helper。其他倉庫檔案不作為解答來源。
  • 不需寫 main、_start、啟動碼或停機機制；練習用的 Bubble Sort、Factorial、Fibonacci 不須另交。

來源：2026 §1.5、1.6、2.1、3.1。

02｜Merge Sort 完整功能規格正式要求
  • size 為 uint32_t，0～128；特別涵蓋 0、1、127、128。
  • 元素為 signed int32_t，涵蓋 −2147483648～2147483647；負數、0、重複、全相等都要處理。
  • 必須 Merge Sort；不要求 stable sort。結果寫回原陣列，可用合法輔助工作區。
  • size=0 時 a0 合法且對齊，但不能存取任何元素。size=1 應保留原值。
  • 只操作 array[0]～array[size−1]；排序不能遺失或增加元素。
輸入： [3, -1, 2, -1]
輸出： [-1, -1, 2, 3]

元素比較用 blt/bge，不要用 unsigned 比較負數，也不要用相減的正負判斷大小：極值相減可能溢位。索引和長度是非負數，可採 unsigned 比較。

來源：2026 §1.1、3.2、3.5；元素數量與值保存為排序正確性的驗證方式。

03｜排序實作分解與地址計算實作建議
  1. 長度 ≤1 返回。
  2. 分割左右區間，分別排序。
  3. 比較左右尚未取出的元素，把較小者寫入暫存。
  4. 補入另一側剩餘元素。
  5. 將暫存結果複製回原陣列。
sort_range(array, temp, left, right):  # 半開區間 [left,right)
    if right-left <= 1: return
    mid = left + ((right-left) >> 1)
    sort_range(array, temp, left, mid)
    sort_range(array, temp, mid, right)
    merge 兩側至 temp，並寫回 array[left:right]

半開區間是建議，不是規格；迭代 bottom-up 也可實作 Merge Sort。128 個 int32_t 暫存需要 512 bytes，可用合法 .bss 或有界 stack。避免每層重複配置完整大陣列。

# t0 = index；a0 = array，這是教學片段
slli t1, t0, 2
add  t1, a0, t1
lw   t2, 0(t1)

每元素 4 bytes，所以地址偏移為 index×4。合併不可提早覆盖未讀元素。遞迴後仍需要的 array、temp、left、right、mid 必須保存。標準 Merge Sort 時間 O(n log n)、工作陣列 O(n)。

04｜4×4 Sudoku 輸入與輸出正式要求

16 個 int32_t，以 row-major 儲存。棋盤 4×4，宮格 2×2；0 是唯一空格，1～4 是固定線索。輸入保證合法且至少一解；不測非法或無解棋盤。

board[row*4 + col]
byte_offset = (row*4 + col)*4

輸入             一個合法輸出
2 4 0 0          2 4 1 3
3 1 0 2          3 1 4 2
0 3 0 4          1 3 2 4
0 2 3 1          4 2 3 1
  • 16 格皆為 1～4，不能殘留 0。
  • 每列、每行、每個宮格各含 1、2、3、4 一次。
  • 原始非零線索不得改動。
  • 多解時任一合法解可接受；搜尋演算法與順序不限。
  • 測試包含已完成、單一空格、少線索、全空與多解棋盤。

來源：2026 §3.3、3.5。上例解答為教學展示。

05｜回溯開發與成功保留答案實作建議
solve(board) -> bool:
    找第一個 0
    沒空格：return true
    for value in 1..4:
        if 同列、同行、同宮格皆允許:
            board[cell] = value
            if solve(board): return true
            board[cell] = 0
    return false

只有失敗才清 0！成功後立即一路返回，否則會把完成的解清掉。

內部 helper 可回傳 bool，但外部 sudoku_solver 仍是 void。wrapper 呼叫 helper 也要保存 ra。每層保存 board 指標、cell、候選值；a/t 暫存器不保證跨 call 保留。

row = index >> 2
col = index & 3
box_row = row & ~1
box_col = col & ~1

列檢查 board[row*4+k]，行檢查 board[k*4+col]，k=0..3；宮格檢查 (box_row+dr,box_col+dc)，dr、dc=0,1。固定乘除 4 可用 shift，不需 mul/div。只找原本空格試填，避免改掉線索。

06｜RV32I、符號與 ABI正式要求
項目正式規則
指令RV32I／ILP32；不可用 mul/div/rem、RVC、浮點或其他擴充
組譯直接 GNU assembler，不經 C preprocessor；不依賴 #include/#define；禁 .include/.incbin
偽指令／macro允許，但展開後必須合法 RV32I；li/la/call 不一定是一條指令
全域符號merge.S 恰一個 array_sort；sudoku.S 恰一個 sudoku_solver；入口可執行且 4-byte 對齊
保留 skeleton保留 .global、.type、.align、入口標籤；helper 私有
禁止自行定義my_printf、_start、__global_pointer$、__lab2_*
外部符號唯一可選 undefined external symbol 為 my_printf
a0～a7、t0～t6Caller-saved；跨 call 仍要用的值由 caller 保存
s0～s11Callee-saved；改了就恢復
ra呼叫 helper 或遞迴前保存本層返回位址
sp全程 16-byte 對齊；frame 為16倍數；返回精確恢復
gp、tp不得修改
完成正確返回位址 ret；禁用 ecall/ebreak/MMIO 代替返回
# 非 leaf 函式教學骨架，依實際需求增加保存空間
addi sp, sp, -16
sw ra, 12(sp)
sw s0, 8(sp)
mv s0, a0
call helper
lw s0, 8(sp)
lw ra, 12(sp)
addi sp, sp, 16
ret

所有提前返回也要走正確 epilogue。每層遞迴需要獨立 frame。Leaf 若不呼叫其他函式、不改 s 暫存器，可無 frame。

來源：2026 §1.4、3.4。

07｜Bare-metal 與記憶體限制正式要求
資源上限
每個 .S256 KiB
.text + .rodata4 KiB
.data + .bss4 KiB
.rodata + .data + .bss4 KiB
全部活動 frame 共用 stack8 KiB

限制同時成立；原始檔 bytes 不等於機器碼 bytes。無 heap，不能 malloc/free/new 或自行假設一塊未授權 RAM。僅可存取合法輸入、自己的 static data 和配置好的 stack。不可寫 text/rodata；lw/sw 4-byte 對齊，其他 load/store 也須自然對齊。

Runtime 載入 ELF、每個測試重置記憶體與暫存器、初始化 sp/gp/tp 與參數，直接啟動入口。不能靠上一測試的狀態。my_printf 只供 debug，共同支援 %c、%d、%s；call 後 a/t/ra 可能變動。

來源：2026 §2、3.4.4。

09｜開發順序與易錯點實作建議
  1. 取得今年 skeleton、README、CMakeLists.txt，確認入口與本地測試方法。
  2. 先以 C／偽碼確認演算法，再規劃暫存器與 stack frame。
  3. 完成排序：base case → 分割 → merge → 寫回；驗證 signed 極值。
  4. 完成數獨：找0 → 檢查約束 → 試填 → 成功保留／失敗復原。
  5. 檢查所有返回路徑、ra、s 暫存器、sp 和記憶體範圍。
  6. 建置與本地驗證，commit/push/submit，確認正式結果。
常見錯誤修正方向
負數排序錯元素使用 signed branch
size=0 越界任何 lw/sw 前處理 base case
array[i] 地址錯偏移 i×4，不是 i
遞迴返回亂跳每層保存 ra 與活動狀態
數獨成功卻留下0成功立即回傳；僅失敗清0
修改原始線索只試填0格
舊版空格−1改為今年0
只通過範例增加极值、重复、空棋盘等验证
印出正解卻被判錯寫回原緩衝區
push後沒成績建立正式 gh student submit
