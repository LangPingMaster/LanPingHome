先看整體：電路、標準元件與面積

這份 ALU.sv 描述 32 位元組合邏輯。教材將它整理成 52 個可點選的基本電路與連線觀察項目，涵蓋加減、位元邏輯、比較、移位、乘法、浮點、飽和運算、計數、控制與選擇等。52 是教材清單項目數，包含介面和設計觀察，且部分功能有重疊，並不等於實體電路的數量。

標準元件數量：目前無法可靠估計。　總面積：目前無法可靠估計。
原因是尚缺 8 個被 include 的乘法／浮點子模組、目標標準元件 .lib、合成設定與報告。面積會受到製程、可用 cell、時序限制、資源共用及最佳化影響。下方④的數字僅為可自行調整的教學假設，不能加總當作 ALU 總面積。

RTL、電路與標準元件的關係

程式中的 +、&、case 描述硬體功能；合成工具可能將其映射為加法邏輯、MUX、AND、XOR、AOI/OAI 等標準元件。工具也可能共享、拆解或最佳化電路，因此不能依本頁直接推斷實際 cell 數量與面積。

要確認實際結果，需要合成 netlist、使用的 cell library 和面積報告。這個檔案沒有 clock／always_ff，描述組合邏輯；CPU 其他模組仍可能含暫存器。

範例 1｜共用 ADD／SUB 的 32-bit 加法路徑

原位置：第 58 行；僅重構一般 f3=0 的運算，不更動其他運算。

左視窗｜原始程式碼：第 15～17、57～58 行

15  logic [31:0] rhs;integer i,cnt;logic signed [9:0] lane;
16  logic [4:0] rotate_amount;
17  assign rotate_amount = 5'd0 - b[4:0];
      ＋ 新增位置：原第 17 行之後 — 在 module 層新增 do_sub、addsub_result 與 assign。
      ⋮ 中間省略其他原始碼 ⋮
57  else case(f3)
58  0:y=(opcode==7'h33 && f7==7'h20)?a-rhs:a+rhs;
      ↳ 以右側 case 分支取代此行。

右視窗｜修改後：共用加減法路徑

// module 層新增
logic do_sub;
logic [31:0] addsub_result;
assign do_sub = (opcode==7'h33 && f7==7'h20);
assign addsub_result = a + (rhs ^ {32{do_sub}}) + {31'd0, do_sub};

// 以這行取代原本 case 的第 58 行
0: y = addsub_result;

原理：do_sub=0 時為 a+rhs；do_sub=1 時為 a+(~rhs)+1，低 32 位等於 a-rhs。ADD／ADDI 原有 rhs 的選擇仍保留。

rhs→32-bit XOR 條件反相→共用加法與進位→y
觀察可能變化
基本電路若原先建立獨立加法器、減法器，可改為共用運算路徑；加入條件反相和進位輸入。
標準元件可能減少重複的進位邏輯及輸出 MUX，增加 XOR／XNOR 等；實際 mapping 未知。
面積與限制可能下降，也可能不變或變大：工具可能本來已共用；寫法或時序約束可能改變結果。

為什麼有機會減少面積？

如果原本合成結果真的同時建立一組加法電路、一組減法電路，再用 32-bit 輸出 MUX 選結果，改寫後可讓兩種運算使用同一組進位與和的邏輯。可能節省的是重複的進位鏈、求和邏輯與部分輸出選擇 cell；同時要新增條件 XOR 和控制進位，所以省下的面積是兩者差額。

示意公式：原面積 ≈ 加法器 + 減法器 + 輸出選擇；修改後 ≈ 共用加法器 + 條件反相 + 控制。只有當被省下的部分大於新增的部分，面積才會變小。工具可能早已自動共享，或建立不同結構，因此面積可能不變甚至增加，時序也可能變差。

測試：5+3=8、5−3=2、0−1=0xffffffff，以及溢位與隨機輸入。比較所有相關控制組合，確保 ADDI、ADD、SUB 相同。

範例 2｜CPOP 計數器改用 6 位元

原位置：第 15、54 行；保留原有 integer cnt 供 CLZ、CTZ 使用，新增專用 6-bit popcnt。32 個位元中最多有 32 個 1，0～32 可用 6 位元表示。

左視窗｜原始程式碼：第 15、19～20、51～55 行

15  logic [31:0] rhs;integer i,cnt;logic signed [9:0] lane;
      ＋ 新增位置：原第 15 行之後 — 新增 logic [5:0] popcnt；原本 cnt 保留供其他功能使用。
      ⋮ 中間省略其他原始碼 ⋮
19  always_comb begin
20  rhs=(opcode==7'h13)?imm:b;y=32'd0;cnt=0;lane=10'sd0;
      ＋ 新增位置：原第 20 行之後 — 在 always_comb 加入 popcnt = 6'd0; 作為預設值。
      ⋮ 中間省略其他原始碼 ⋮
51   case(imm[4:0])
52   0:begin cnt=0;for(i=31;i>=0;i=i-1) if(!a[i] && cnt==(31-i)) cnt=cnt+1;y=$unsigned(cnt);end
53   1:begin cnt=0;for(i=0;i<32;i=i+1) if(!a[i] && cnt==i) cnt=cnt+1;y=$unsigned(cnt);end
54   2:begin cnt=0;for(i=0;i<32;i=i+1) cnt=cnt+int'({31'd0,a[i]});y=$unsigned(cnt);end
      ↳ 整行以右側 6-bit CPOP 分支取代；其他分支不變。
55   default:y=0;endcase

右視窗｜修改後：新增 6-bit 計數器

// module 層新增，原有 cnt 保留
logic [5:0] popcnt;

// always_comb 預設值區新增
popcnt = 6'd0;

// 取代 case (imm[4:0]) 中的第 54 行
2: begin
  popcnt = 6'd0;
  for (i=0; i<32; i=i+1)
    popcnt = popcnt + {5'd0, a[i]};
  y = {26'd0, popcnt};
end

範例：a=0x0000000b 輸出 3；a=0xffffffff 輸出 32。6 位元足以容納迴圈每一步的結果。

32 個輸入 bit→6-bit 累加／計數網路→高 26 位補零→y
觀察可能變化
基本電路明確限定 CPOP 的計數寬度，可能減少不必要的高位加法與進位邏輯。
標準元件可能減少 XOR、AOI/OAI、AND／OR 等加法邏輯 cell；具體類型依 mapping 而定。
面積與限制若工具已推導有效位元，面積可能不變。此寫法仍可能形成長的組合路徑，必須檢查時序。

為什麼有機會減少面積？

原本 integer cnt 為 32-bit；CPOP 的合法結果只有 0～32，6 bit 足夠。若原合成電路仍保留不必要的高位運算，限制為 6 bit 可減少高位的加法、進位與相關選擇邏輯，進而可能減少 XOR、AND、AOI/OAI 等 cell 的總面積。高 26 位固定補零，本身不表示需要 26 個新的加法器。

這不是保證：工具可能已從原始程式推導出高位無用，或採用不同加法樹；最後面積及關鍵路徑都要比較。

測試全零、全一、單一 bit 及隨機輸入，並與原版逐一比較；也要確定 CLZ／CTZ 的行為未受影響。

範例 3｜刪除被覆蓋、無作用的 y 指定

原位置：第 49～55 行。第 50 行的 y=0 在後續 case 每個分支及 default 均重新指定 y，因此此處指定不影響最終結果。

左視窗｜原始程式碼：第 49～56 行

49  else if(opcode==7'h13 && f7==7'b0110000 && f3==1) begin
50   if(b==32'hffffffff) y=0;
      ↳ 只刪除此行；後方 case 的每個分支均會重新指定 y。
51   case(imm[4:0])
52   0:begin cnt=0;for(i=31;i>=0;i=i-1) if(!a[i] && cnt==(31-i)) cnt=cnt+1;y=$unsigned(cnt);end
53   1:begin cnt=0;for(i=0;i<32;i=i+1) if(!a[i] && cnt==i) cnt=cnt+1;y=$unsigned(cnt);end
54   2:begin cnt=0;for(i=0;i<32;i=i+1) cnt=cnt+int'({31'd0,a[i]});y=$unsigned(cnt);end
55   default:y=0;endcase
56  end

右視窗｜修改後：刪除被覆蓋的指定

else if(opcode==7'h13 && f7==7'b0110000 && f3==1) begin
  // 移除 if(b==32'hffffffff) y=0;
  case(imm[4:0])
    0:begin cnt=0;for(i=31;i>=0;i=i-1) if(!a[i] && cnt==(31-i)) cnt=cnt+1;y=$unsigned(cnt);end
    1:begin cnt=0;for(i=0;i<32;i=i+1) if(!a[i] && cnt==i) cnt=cnt+1;y=$unsigned(cnt);end
    2:begin cnt=0;for(i=0;i<32;i=i+1) cnt=cnt+int'({31'd0,a[i]});y=$unsigned(cnt);end
    default:y=0;
  endcase
end
b 與全 1 比較→條件指定 y=0→後續 case 覆蓋 y
觀察可能變化
基本電路移除這一處不影響輸出的比較及條件選擇；b 在其他運算仍有用途，不能刪除 b。
標準元件理論上可能省下此條件的比較、選擇邏輯對應的 cell；但一般工具很可能早已消除此死碼。
面積與限制因此面積很可能完全不變，這是程式整理與驗證例子，不保證節省面積。

為什麼可能減少面積，又可能完全不變？

如果工具未消除這段無效指定，刪掉它可能移除 b 與全 1 的相等比較邏輯，以及該次 y 選擇所需的邏輯 cell。但後面的 case 每個分支（含 default）都重新指定 y，這一指定不會影響最終輸出，合成工具通常會自動消除它。

因此修改前後的合成 netlist 很可能相同、面積差為 0；本例不能承諾降低面積。b 在其他功能仍有作用，不能因此移除 b 或它的其他電路。

測試 b 全 1 與其他值，搭配 imm 的 0、1、2、其他值；以原版與新版逐一比對。不要刪除 case 的 default，也不要把此例當作已量測的面積節省。

比較公式：面積變化 = 修改後 Total cell area − 修改前 Total cell area；縮減百分比 = (修改前 − 修改後) ÷ 修改前 × 100%。需使用相同 library、合成工具、約束、完整子模組與測試條件，也要比較時序；本頁無實測數據，不提供虛構數值。
