總覽｜Controller 的功能、電路與面積

本檔案共 6 行，定義 9 個單位元輸入及 3 個單位元輸出；由三條連續指定敘述組合控制邏輯。教材整理 11 個可選取的電路與連線觀察項目；項目有重疊，並非實際電路數量。

無法直接確定標準元件數量或面積。 需要實際合成工具、標準元件 .lib、時序與負載約束、netlist 和報告。不同控制輸出可能共享邏輯；不要將各項試算相加。

程式依可見邏輯運作；訊號與 CPU 其他模組的完整時序和規格需查閱其他檔案。本頁未對整個 CPU 的功能或作業分數作保證。

④ 標準元件與面積試算

下列計算只是假設，並非由此 Controller 合成推算。不同 cell 通常有不同面積，實際面積為 Σ（各類 cell 顆數 × 對應面積）；單位應依實際 library 與報告確認。

例如假設 10 顆、每顆 1 µm²，得到 10 µm²；此數值不是本電路估計值。標準元件面積也不等於含空白與繞線需求的核心面積。

範例 1｜共用分支與跳躍偵測

左｜原始程式碼及行號

＋ 原第 2 行之後：在原第 2 行之後新增 logic control_flow 與 assign；保留第 3 行。
3 assign advance=!mem_hold;
4 assign redirect=ev&&(ebranch||ejump)&&branch_taken&&!mem_hold;
5 assign fetch_req=!rst&&!pending&&!dv&&!load_bubble&&!mem_hold&&!(ev&&(ebranch||ejump));

右｜建議修改後程式碼

// 原第 2 行之後新增
logic control_flow;
assign control_flow = ev && (ebranch || ejump);

// 原第 3 行保留
assign advance = !mem_hold;
// 取代原第 4、5 行
assign redirect = control_flow && branch_taken && !mem_hold;
assign fetch_req = !rst && !pending && !dv && !load_bubble && !mem_hold && !control_flow;

基本電路、標準元件與面積為什麼可能改變？

原第 4、5 行都有 ev && (ebranch || ejump)。若工具原本建立兩份判斷邏輯，可以共用一份 OR 與 AND 邏輯，可能減少相關標準元件；但共享可能增加扇出、需要 buffer，且工具通常已自動合併，因此面積可能不變或增加。

如何驗證：涵蓋 ev、ebranch、ejump、branch_taken、mem_hold 的組合，並確認 fetch_req 不依賴 branch_taken。

各例互相獨立；同時套用時應重新檢查重複宣告與功能。

範例 2｜共用 !mem_hold 與 advance

左｜原始程式碼及行號

＋ 無新增宣告：原第 3 行的 advance 已等於 !mem_hold。
3 assign advance=!mem_hold;
4 assign redirect=ev&&(ebranch||ejump)&&branch_taken&&!mem_hold;
5 assign fetch_req=!rst&&!pending&&!dv&&!load_bubble&&!mem_hold&&!(ev&&(ebranch||ejump));

右｜建議修改後程式碼

// 第 3 行保留
assign advance = !mem_hold;
// 用 advance 取代第 4、5 行的 !mem_hold
assign redirect = ev && (ebranch || ejump) && branch_taken && advance;
assign fetch_req = !rst && !pending && !dv && !load_bubble && advance && !(ev && (ebranch || ejump));

基本電路、標準元件與面積為什麼可能改變？

三處反相都是同一訊號，假如原先未共享，使用 advance 可能共用反相電路並減少 INV；但合成常會自動共享、吸收反相，或因扇出插入緩衝，因此面積未必下降。實體設計和時序可能影響結果。

如何驗證：檢查 mem_hold 為 0、1 與 X/Z 時三個輸出；這是一個連續指定的組合網路，部分模擬器在 delta cycle 內可能短暫顯示中間值，應在訊號穩定後比較。

各例互相獨立；同時套用時應重新檢查重複宣告與功能。

範例 3｜以 OR 後反相表示取指阻擋

左｜原始程式碼及行號

＋ 無新增宣告；僅重寫原第 5 行，保留第 3、4 行。
3 assign advance=!mem_hold;
4 assign redirect=ev&&(ebranch||ejump)&&branch_taken&&!mem_hold;
5 assign fetch_req=!rst&&!pending&&!dv&&!load_bubble&&!mem_hold&&!(ev&&(ebranch||ejump));

右｜建議修改後程式碼

// 第 3、4 行原樣保留
assign advance = !mem_hold;
assign redirect = ev && (ebranch || ejump) && branch_taken && !mem_hold;
// 取代原第 5 行：任一阻擋成立就禁止取指
assign fetch_req = !(rst || pending || dv || load_bubble || mem_hold || (ev && (ebranch || ejump)));

基本電路、標準元件與面積為什麼可能改變？

依德摩根定律，原本多個 NOT 後 AND，可改寫為阻擋條件 OR 後 NOT。若目標 library 有適合的多輸入 NOR 或複合閘，可能以較少 cell 實作；但也可能合成成相同電路，或因扇入、時序與 buffer 而變大。必須使用同一 library 與約束比較。

如何驗證：測試所有 9 個輸入的二態組合及重要 X/Z 情況，以穩定後的輸出比對原版；重寫保持 branch_taken 不參與 fetch_req。

各例互相獨立；同時套用時應重新檢查重複宣告與功能。

比較方法：修改前後使用相同合成工具、library、約束與頂層，檢查功能等價、Total cell area、cell 數量和時序。節省率 =（修改前面積 − 修改後面積）÷ 修改前面積 × 100%。
