02｜Windows PowerShell 開啟 WSL

先確認 Docker Desktop 正在執行。在 Windows 開啟 PowerShell：附件中你位於 E:\GitHub\CO\Lab1\Docker-Environment。輸入下列命令進入 WSL。

Windows PowerShell
(base) PS E:\GitHub\CO\Lab1\Docker-Environment> wsl

成功時提示字元變成 wolf@Peng2023:/mnt/e/GitHub/CO/Lab1/Docker-Environment$。PS 已消失，代表現在正在 WSL。

如果是直接開啟 Ubuntu 終端機而沒有位於該資料夾，先在 WSL 執行：

WSL bash
cd /mnt/e/GitHub/CO/Lab1/Docker-Environment
ls

你的附件中 ls 顯示 Dockerfile、attach.sh、config、create.sh。這表示接下來的 ./attach.sh 位於目前目錄。

在 WSL 輸入 cd /home/ubuntu/workspace 會得到「No such file or directory」；那是容器內路徑，須先進入 Docker。單獨輸入 docker 只會列出幫助，不會進入容器。

03｜由 WSL 進入課程 Docker 容器

從剛才含 attach.sh 的資料夾執行：

WSL bash：wolf@Peng2023
bash ./attach.sh

看到 Welcome to fish, the friendly interactive shell 與 ubuntu@docker-desktop ~/workspace>，表示進入容器；~ 對這個使用者是 /home/ubuntu，因此 ~/workspace 即 /home/ubuntu/workspace。

從這裡開始，金鑰、SSH 驗證及 Git clone 都在 Docker 終端機執行。可以用 pwd 和 ls 觀察目前位置與檔案。

04｜在 Docker 首次建立 SSH 金鑰

這是首次設定才要執行的一次性步驟。附件顯示你已建立 id_ed25519 與 id_ed25519.pub；目前使用同一容器時，直接跳到「讀取公鑰」即可。若是全新容器且確實沒有金鑰，執行：

Docker fish：ubuntu@docker-desktop
ssh-keygen -t ed25519 -C "E24144773 GitHub"

系統詢問 Enter file in which to save the key (/home/ubuntu/.ssh/id_ed25519): 時按 Enter 採用預設路徑。接著可設定密碼片語；若選擇空白，兩次提示均按 Enter。若看到「檔案已存在／Overwrite」，請先停止確認；不要覆蓋目前 GitHub 已註冊的金鑰。

成功訊息（節錄）
Your identification has been saved in /home/ubuntu/.ssh/id_ed25519
Your public key has been saved in /home/ubuntu/.ssh/id_ed25519.pub

id_ed25519 是私鑰，只能留在容器中；id_ed25519.pub 是可加到 GitHub 的公鑰。執行下列命令印出完整公鑰：

Docker fish
cat ~/.ssh/id_ed25519.pub

輸出會是一整行，以 ssh-ed25519 開頭，以 E24144773 GitHub 結尾；必須完整複製這一行。請勿把私鑰 ~/.ssh/id_ed25519 的內容貼到 GitHub 或聊天紀錄。

05｜在 GitHub 網頁註冊公鑰

於 Windows 瀏覽器登入 E24144773 的 GitHub 帳號，打開 https://github.com/settings/keys，在「SSH keys」按 New SSH key：

欄位填寫內容
Title例如 CO Lab1 Docker，讓自己能辨識是哪個容器。
Key typeAuthentication Key
Key貼上 cat ~/.ssh/id_ed25519.pub 的完整一行內容。

按 Add SSH key 儲存；如果原有金鑰已存在，無須重複新增。附件的 GitHub 畫面顯示該帳號已有 Authentication key。

之前建立的 fine-grained token 顯示 Pending，屬 HTTPS Token 的授權狀態。本流程使用 SSH 網址 git@github.com:…；HTTPS 的 Password 提示不可輸入 GitHub 登入密碼。

06｜在 Docker 驗證 GitHub，下載個人作業

先確認仍在 ubuntu@docker-desktop。第一次連 GitHub 時，SSH 可能問 Are you sure you want to continue connecting (yes/no/[fingerprint])?。先與 GitHub 官方主機指紋頁核對，符合才輸入完整的 yes；只輸入 y 不夠。接受主機身分只是將它加入 known_hosts，還須有帳號公鑰授權。

Docker fish：檢查 SSH 身分
ssh -T git@github.com
Hi E24144773! You've successfully authenticated, but GitHub does not provide shell access.

看到 Hi E24144773! 即認證成功。此指令不提供 GitHub shell，因此 fish 後面顯示 [1] 也不表示 SSH 金鑰失敗。

確認在 ~/workspace，然後用一整行執行 SSH URL 的 clone。若儲存庫資料夾已存在，略過 clone，直接 cd 進去。

Docker fish：下載與檢查
cd ~/workspace
git clone git@github.com:Computer-Organization-at-NCKU-EE/fall-2026-lab1-e24144773.git
ls
cd fall-2026-lab1-e24144773
ls

附件中的成功輸出包含 Receiving objects: 100% (47/47)、Resolving deltas: 100% (4/4)，進入目錄後有 CMakeLists.txt、README.md、include/、report.md、riscv-tests/、src/、tests/。

若要依作業規定繼續設定測試環境，留在容器內的儲存庫根目錄執行以下指令；附件沒有顯示其執行結果，所以這些是後續待執行的步驟：

Docker fish：後續作業準備（尚未見於附件成功紀錄）
git submodule update --init --recursive
pre-commit install
git submodule status

在 fish 輸入 cd.. 會被當成不存在的指令；要回上一層是 cd ..（中間一個空格）。若目的是回到 WSL，直接輸入 exit。

07｜回到 WSL，用 docker cp 複製資料到 Windows

先從 Docker 的 fish 終端退出。你應看到提示字元從 ubuntu@docker-desktop 返回 wolf@Peng2023：

Docker → WSL
exit

在 WSL 執行 docker ps；附件顯示課程容器的名稱是 comporg_Lab1-dev-container。其中 Lab1 的 L 是大寫，Docker 容器名稱必須完全相同。

WSL bash：核對容器
docker ps

確認 Windows 目的地資料夾存在後，在 WSL 執行下列一整行；冒號左邊是容器名稱，冒號右邊是容器裡的來源路徑，最後是 WSL 對應 Windows E 槽的目的地：

WSL bash：真正執行複製（單行）
docker cp comporg_Lab1-dev-container:/home/ubuntu/workspace/fall-2026-lab1-e24144773 /mnt/e/GitHub/CO/Lab1/

你的附件顯示 Successfully copied 183kB to /mnt/e/GitHub/CO/Lab1/，代表此次複製成功；往後檔案增減時，顯示的大小可能不同。

可先從 WSL 確認資料夾存在，再用 Windows 檔案總管輸入下列路徑：

WSL bash：檢查目標
ls /mnt/e/GitHub/CO/Lab1/fall-2026-lab1-e24144773
Windows 檔案總管位址列
E:\GitHub\CO\Lab1all-2026-lab1-e24144773

docker cp 是單次複製，不會自動同步。此後若在 Docker 裡修改程式，需要再次決定如何更新 Windows 副本；若在 Windows 副本修改程式，也不會自動回到容器。重新複製到既有路徑前，請先核對目標，以免建立巢狀資料夾或蓋掉修改。

08｜常見問題：從附件中的錯誤得到的正確做法

現象處理方式
WSL 執行 cd /home/ubuntu/workspace 失敗那是 Docker 使用者的路徑；先在 WSL 執行 bash ./attach.sh。
HTTPS Invalid username or token、403附件的 HTTPS 認證未成功；本流程使用已驗證的 SSH 金鑰和 git@github.com:… URL。
Permission denied (publickey)先在 Docker 建立金鑰、將公鑰加入正確的 GitHub 帳號，再以 ssh -T git@github.com 驗證。
首次主機確認輸入 y 後仍等待核對 GitHub 官方主機指紋後，輸入完整 yes。
git clone git clone … → Too many argumentsgit clone 只寫一次。
fish 的 cd.. → Unknown command要加空格，改用 cd ..。
Docker 裡的 docker ps → Unknown command輸入 exit 回 WSL，再執行 docker ps 與 docker cp。
