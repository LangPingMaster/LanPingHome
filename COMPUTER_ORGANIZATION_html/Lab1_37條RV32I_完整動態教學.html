PC 教學示意軌跡

這 37 個頁面是「各指令獨立的教學 Case」，不是宣稱它們真的組成同一支可直接執行的 37-instruction 程式。下方 PC 僅用來示範各類指令如何產生 new_pc：一般 instruction 預設 PC+4；此處 Branch 範例刻意設定為 taken，因此示範 PC+8；JAL 示範 PC+16；JALR 則使用該 Case 指定的 rs1+imm 目標。每個 Case 的 register/memory 執行前狀態也是獨立設定，目的是讓該 instruction 的效果清楚可見。

本版審核後的重要校正

① 37 條指令：依附件 src/inst.h，必要指令確實是 OP 10 + OP-IMM 9 + LOAD 5 + STORE 3 + BRANCH 6 + JAL/JALR/AUIPC/LUI 各 1 = 37； inst_invalid 是額外的無效分類，不算第 38 條作業指令。

② enum 數值：inst_add=0，之後依宣告順序遞增到 inst_lui=36； inst_invalid=37。這是因為附件 enum 沒有另外指定整數值。

③ Fetch：附件 Core_fetch() 從 current_pc 經 MemoryMap 讀 4 bytes， 按 little-endian 組成 inst_fields_t.raw。

④ Decode：輸出 inst_enum_t，不在此階段修改 register 或 memory。 inst_sll 等名稱表示「辨識出的指令種類」，不是 ALU 計算結果。

⑤ Execute / PC：Core_execute() 先令 new_pc=current_pc+4； Branch taken、JAL、JALR 可覆寫。Register write-back 與 LOAD/STORE memory side effect 在 Execute 內完成； Core_update_pc() 最後才做 current_pc=new_pc。

⑥ 37 個 Case 的關係：本頁每個 Case 的 operand/register/memory 初值是獨立的教學設定， 因此不可把 37 個 Case 的 register state 誤解成同一支程式逐條自然延續的完整 architectural state。 PC 數字主要用來展示 PC+4、Branch、JAL、JALR 的規則。
