先看懂這份作業

你要以 C 語言完成一個功能式 RV32I 指令集模擬器（ISS），支援講義規定的 37 個指令。模擬器每次執行一個指令，依序進行 Core_fetch() → Core_decode() → Core_execute() → Core_update_pc()。你的主要工作在 Decode 與 Execute。

在哪個系統做？在 Windows 電腦安裝並開啟 Docker Desktop，於 WSL／Ubuntu 終端機執行 Lab 0 指令，進入助教提供的 Docker 容器；在容器內複製、編譯和測試作業。macOS 使用終端機與教材的 macOS 分支。Windows PowerShell 可用於啟動與檢查 Docker，但講義要求後續作業指令在課程容器內操作。

交哪些檔案？只預期修改 src/core.c 與 report.md；前者由程式評分器讀取已提交版本，後者由助教另行評閱。勿更動測試、CMake、submodule 或自動評分工作流程。

步驟 01

安裝並進入課程開發環境

  1. Windows：啟用「Windows 子系統 Linux 版」和「虛擬機器平台」，安裝 WSL／Ubuntu、Git 和 Docker Desktop；開啟 Docker Desktop，等待狀態顯示 Engine running，確認 Docker Desktop 與 WSL 已連動。
  2. 打開 Ubuntu（WSL）終端機，先檢查 Docker：
docker --version

在 Ubuntu 終端機下載助教的課程映像：

docker pull ghcr.io/computer-organization-at-ncku-ee/co-docker-env:latest

接著下載環境啟動工具（這個 repository 不是你的 Lab 1 作業）：

git clone https://github.com/Computer-Organization-at-NCKU-EE/Docker-Environment.git
cd Docker-Environment
bash -c "sed -i 's/\r$//' ./create.sh"
bash ./create.sh comporg
bash ./attach.sh

macOS 請依環境講義改用：

git clone https://github.com/Computer-Organization-at-NCKU-EE/Docker-Environment.git
cd Docker-Environment
git switch macos
./create.sh comporg
./attach.sh
執行 attach.sh 後，你應已進入容器。講義建議將作業放在容器的 /home/ubuntu/workspace，因為該路徑有持久化儲存。Lab 1 的建置與測試指令均在容器內、作業 repository 根目錄執行。

步驟 03

在容器中複製專案並初始化

回到已進入課程容器的終端機，切換至持久化的工作區；將下方尖括號部分換成你自己的網址及實際資料夾名稱：

cd /home/ubuntu/workspace
git clone <你的專屬 repository URL>
cd <複製後的資料夾名稱>
git submodule update --init --recursive
pre-commit install

確認目錄內有 CMakeLists.txt、src/、tests/ 和 report.md，再檢查工具：

git submodule status
cmake --version
riscv32-unknown-elf-gcc --version
pre-commit --version

若 git submodule status 的行首是 -，再執行一次 git submodule update --init --recursive。若找不到交叉編譯器或 pre-commit，先確認你已透過 attach.sh 進入課程容器。

步驟 04

編寫 src/core.c 和 report.md

依主講義先讀 §3.1–3.4 了解架構；實作時參照第 2 章指令表與 §3.6–3.8。開啟 src/core.c，補完：

  • Core_decode()：依 opcode，並在需要時檢查 func3／func7，辨認正確的 inst_enum_t。starter code 已有 JAL、JALR、AUIPC、LUI 的 opcode 分類，其餘需要補齊。
  • Core_execute()：依解碼結果讀取暫存器、運算，更新目的暫存器、記憶體或 new_pc。一般指令預設 new_pc = current_pc + 4；跳躍或成立的分支另算目標位置。
  • 保證 x0 永遠為 0；正確拼接各格式立即數並做符號延伸；區分 signed 與 unsigned 比較、移位和 load。
  • LOAD／STORE 透過 MemoryMap_generic_load/store 存取；依 1、2、4 byte 長度處理小端序，LOAD 的符號延伸要由 Execute 實作。
  • 填妥 report.md 的姓名、學號及各題回答；現有報告還含加分題。

有需要時查看 src/inst.h（編碼與 enum）、include/arch.h（PC／暫存器）、src/mem_map.h（記憶體介面）。閱讀它們即可；正式評分僅取已提交的 src/core.c，報告另行計分。

步驟 05

在作業根目錄編譯與測試

首次 clone 後先建立 RISC-V 指令測試程式，接著編譯模擬器：

make -C riscv-tests/isa -j
cmake -S . -B build
cmake --build build --parallel
ctest --test-dir build -N
ctest --test-dir build --output-on-failure

ctest -N 正常應列出 37 個測例。修改 src/core.c 後，通常只要重跑 cmake --build build --parallel 和 CTest。只測 ADD 或避免除錯時卡住：

ctest --test-dir build -R '^OP_add$' --output-on-failure --timeout 10
專案啟用 -Werror，警告也會使編譯失敗。不要為了通過測試而修改 tests/、CMake 設定或停用 -Werror。
步驟 06

提交、推送、確認回傳成功

確認兩份檔案都已完成後，在作業 repository 根目錄執行：

git status
git add src/core.c report.md
git commit -m "feat: complete Lab 1 ISS"
git status --short -- src/core.c report.md
git push

git status --short -- src/core.c report.md 在推送前應沒有輸出，代表最終版本已提交。若 pre-commit 自動修改檔案並中止這次 commit，依序查看 git status、git diff，重新 git add src/core.c report.md 並再執行 git commit；不要使用 --no-verify。

每次推送到預設分支都會建立一次繳交並觸發自動評分。推送後到 GitHub 查看該 commit 狀態，再到 Classroom50 查看該次提交的 Program 詳細成績。不需在 Moodle 上傳 ZIP，也不需另外建立 submission tag。

最後核對：37 個指令、x0 與 PC 行為、報告姓名學號及所有題目、兩份檔案已 commit、截止前 push 到預設分支，並親自查看 Classroom50 結果。講義附件未明列本次作業的確切截止時間；以你的 Classroom50 課程頁面公告為準。
