用一張 2×2 圖片，看懂 RV32I 模擬器怎麼執行程式

繁體中文互動教學｜依據 core_improved(3).c 的取指、解碼、執行與更新 PC 流程

先分清楚兩層程式

圖片處理程式決定像素要變成 0 或 255；core_improved(3).c 則是一個指令集模擬器（ISS），負責逐條執行圖片處理程式編譯出的 RISC-V 指令。它沒有直接解析 PNG 的功能。此處假設圖片已解碼成四個灰階位元組、指令已載入可取指的記憶體，而且記憶體映射涵蓋範例地址。

PNG → 外部解碼像素位元組 → 模擬記憶體RISC-V 程式 → CPU 模擬器結果位元組 → 外部組回圖片

步驟 2：把演算法寫成指令

/* 概念 C 程式：這不是 core_improved(3).c 內建的函式 */
for (int i = 0; i < 4; ++i)
    output[i] = input[i] < 128 ? 0 : 255;

下方是等價的 RV32I 組合語言示意。lui 設定地址、lbu 讀像素、bltu 比較、sb 寫回。右側十六進位 PC 假設程式從 0 開始，每條指令恰好 4 位元組。

PC      指令                     意思
0x00    lui  x5, 0x1             x5 = 0x1000（輸入指標）
0x04    lui  x6, 0x2             x6 = 0x2000（輸出指標）
0x08    addi x7, x0, 4           x7 = 4（剩餘像素數）
0x0c    addi x8, x0, 128         x8 = 128（門檻）
loop:
0x10    lbu  x9, 0(x5)           x9 = 讀入一個無號像素
0x14    bltu x9, x8, black       若像素 < 128，跳往 black
0x18    addi x10, x0, 255        白色像素 = 255
0x1c    jal  x0, save            跳往 save；x0 不保存返回位址
black:
0x20    addi x10, x0, 0          黑色像素 = 0
save:
0x24    sb   x10, 0(x6)          寫一個位元組到輸出
0x28    addi x5, x5, 1           輸入指標 +1
0x2c    addi x6, x6, 1           輸出指標 +1
0x30    addi x7, x7, -1          剩餘數量 -1
0x34    bne  x7, x0, loop        尚有像素就回到 0x10
0x38    /* 範例到此結束：由外部執行器停止 */

本範例沒有使用 addi x6,x0,0x2000，因為 ADDI 的立即數只有 12 位元，不能直接表示 0x2000。使用 lui 才能建立這些位址。core_improved(3).c 本身沒有通用的「停止」指令，最後一行需要外部執行器設定停止條件。

步驟 3：每條指令如何走過模擬器？

PCCore_fetch：讀 4 bytesCore_decode：辨識 opcodeCore_execute：讀暫存器／算術／記憶體Core_update_pc：提交新 PC
模擬器函式實際發生的事例：PC=0x10 的 lbu
Core_fetch依 PC 從映射記憶體讀取 4 bytes，以小端序組為 32 位元指令。取得位於 0x10 的 lbu x9,0(x5) 機器碼。
Core_decode檢查 opcode、funct3、必要時 funct7，產生 inst_enum_t。辨識成 inst_lbu；這一步不修改像素。
Core_execute讀出來源暫存器、重組立即數；依指令選擇 ALU、載入、儲存或分支；必要時寫回目的暫存器。從 x5+0=0x1000 讀 1 byte：30 → x9=30。
Core_update_pc將 new_pc 寫入 current_pc。正常前進至 PC=0x14。

Core_ctor 將 PC 與暫存器歸零並建立映射表；設備需由外部透過 Core_add_device 掛載，像素與機器碼也須由外部載入。Core_dtor 負責結束時釋放映射資源。

步驟 4：按鈕逐像素追蹤

以下一次「下一步」代表處理一個完整像素，其中實際會執行多條指令；上面的表格已展示每一條指令都重複的四階段。

暫存器／資料本次值代表什麼
x5輸入像素的位址
x6輸出像素的位址

x10即將由 sb 寫回的黑或白

對照原始碼中的關鍵位置

本例指令core_improved(3).c 所做的事看得見的效果
lbuMemoryMap_generic_load(..., a + imm_i, 1, bytes)；零延伸寫入 rd。30、180 等像素進入 x9。
bltu以無號數比較 a < b；成立則 new_pc = current_pc + imm_b。30 跳到 black；180 不跳，執行白色路徑。
addiresult = a + imm_i；再寫入非 x0 的 rd。設定 255、指標加 1、計數減 1。
sb取 x10 的低 8 bits，MemoryMap_generic_store(..., a + imm_s, 1, bytes)。逐位元組寫至 0x2000～0x2003。
bne若 a != b，改寫 new_pc；不寫目的暫存器。剩餘像素不為 0 時回到 loop。
