01｜這份作業真正的目的與評分方式

目標是用 C 寫一個 RV32I ISA Simulator（ISS）：讀取 32 位元機器指令，辨識其編碼，依 RISC-V 語意改變暫存器、記憶體與程式計數器 PC。它是用程式模擬「指令對外可觀察的效果」，並非設計 RTL 或實體 CPU。

從 Core 的程式讀起

DECLARE_TICK_TICK(Core) {
    Core *self_ = container_of(self, Core, super);
    inst_fields_t inst_fields = Core_fetch(self_);
    inst_enum_t inst_enum = Core_decode(self_, inst_fields);

current_pc 指目前指令；new_pc 暫放下一條指令的位址；gpr[32] 是整數暫存器；MemoryMap 決定位址落在哪個裝置。硬體示意中的 ALU、byte buffer 是 C 程式運算和 bytes[4] 的類比，並非這份 C 專案另有獨立 RTL。

03｜37 條指令：編碼、功能與各組得分
群組／opcode[6:0]指令件數分數解碼與執行要點
OP / 0110011ADD SUB SLL SLT SLTU XOR SRL SRA OR AND1015R-type，ADD/SUB 與 SRL/SRA 須以 funct7 區分；移位只用 rs2 的低 5 bits。
OP-IMM / 0010011ADDI SLTI SLTIU XORI ORI ANDI SLLI SRLI SRAI915I-type 立即數先符號延伸；shift-immediate 依高位辨識 SRLI/SRAI，shamt 取 5 bits。
LOAD / 0000011LB LH LW LBU LHU58位址 rs1+I-immediate；1/2/4 bytes；LB/LH 符號延伸，LBU/LHU 零延伸。
STORE / 0100011SB SH SW38位址 rs1+S-immediate；取 rs2 低 1/2/4 bytes；不寫 rd。
BRANCH / 1100011BEQ BNE BLT BGE BLTU BGEU68B-immediate 依原 PC 相對跳躍；BLT/BGE 有號，BLTU/BGEU 無號；不寫 rd。
JAL / 1101111JAL14rd = PC+4；新 PC = 舊 PC+J-immediate。
JALR / 1100111JALR14rd = PC+4；新 PC = (舊 rs1+I-immediate)&~1；先讀 rs1 再寫 rd。
LUI / 0110111LUI14rd = 指令 bits[31:12] 放在目的暫存器高 20 bits。
AUIPC / 0010111AUIPC14rd = 舊 PC + U-immediate。

總計 10+9+5+3+6+1+1+1+1 = 37；指令分數 15+15+8+8+8+4+4+4+4 = 70。inst_invalid 是框架哨兵，不是第 38 條指令；FENCE、ECALL、EBREAK、特權指令不在此作業範圍。

組別分數 = half-up(組別最高分 × 該組通過數 ÷ 總件數)。例如 OP 10 題過 9 題：15×9/10=13.5，得 14 分。不同組別並非每條指令分數完全相同。
04｜動手寫 core.c：建議順序與每階段檢查

A. Decode：先 opcode，再 funct3、必要時 funct7

以 inst_invalid 作初值。OP 的 ADD/SUB 共用 funct3=000，SRL/SRA 共用 funct3=101，必須再看 funct7；SLLI/SRLI/SRAI 也要檢查編碼中的高位；JALR 的 funct3 應為 000。避免「只要 opcode 是 OP 就當 ADD」的錯誤。

inst_enum_t ret = inst_invalid;
switch (inst_fields.R_TYPE.opcode) {
case OP:
    if (inst_fields.R_TYPE.func3 == ADD_SUB_FUNC3) {
        if (inst_fields.R_TYPE.func7 == 0) ret = inst_add;
        else if (inst_fields.R_TYPE.func7 == 0x20) ret = inst_sub;
    }
    /* 其餘 OP 指令同理 */
    break;
/* 其餘 opcode */
}
return ret;

B. 重建來源、立即數與符號

格式指令欄位構成常見用途重點
Iimm[11:0] = instruction[31:20]OP-IMM / LOAD / JALR12-bit 符號延伸；SLTIU 的立即數仍要先符號延伸。
Simm[11:5]=[31:25]，imm[4:0]=[11:7]STORErs2 是要儲存的資料，不是目的暫存器。
Bimm[12|10:5|4:1|11|0]=[31|30:25|11:8|7|0]BRANCH有符號、bit0=0、以舊 PC 為基準。
Uimm[31:12]=instruction[31:12]，低 12 bits=0LUI / AUIPCAUIPC 要加舊 PC。
Jimm[20|19:12|11|10:1|0]=[31|19:12|20|30:21|0]JAL有符號、bit0=0、以舊 PC 為基準。

C. Execute：預設 PC+4，依指令覆寫

先讀取 a=gpr[rs1]、b=gpr[rs2]，後續再寫 rd；這也處理 jalr xN,xN,imm。算術、位元運算、比較、移位先寫到 result。LOAD/STORE 經過 MemoryMap；STORE/BRANCH 不寫 rd。最後 rd!=0 才寫回，且保持 gpr[0]=0。

self->new_pc = self->arch_state.current_pc + 4;
const reg_t a = self->arch_state.gpr[rs1];
const reg_t b = self->arch_state.gpr[rs2];
/* switch(inst_enum): compute result / memory side effects / new_pc */
if (write_rd && rd != 0) self->arch_state.gpr[rd] = result;
self->arch_state.gpr[0] = 0;

D. LOAD / STORE 小端序與 JALR 邊界

記憶體位址最小的 byte 是結果 bits[7:0]，下一個 byte 左移 8 bits。LB 若最高資料位為 1，要把高 24 bits 填 1；LH 同理高 16 bits。LBU/LHU 保持高位為 0。JALR 的目標最低位清零，rd 可與 rs1 相同。

LB 與 LBU

讀取 0x80：LB 得 0xFFFFFF80；LBU 得 0x00000080。

JALR 舊值

舊 PC=0x100、舊 x5=0x200、imm=3：新 PC=0x202，新 x5=0x104。

算術右移

SRA/SRAI 要延伸符號位；SRL/SRLI 是無號邏輯右移。

設計目標是符合規格，單純通過公開測試仍須檢查負立即數、位移量 31、x0、分支不成立、rd=rs1 的 JALR 等邊界。不要以修改測試檔或停用 -Werror 取得表面通過。

/*
 * Lab 1：RV32I 指令集模擬器核心（繁體中文教學註解版）
 *
 * 一個指令週期：Core_fetch → Core_decode → Core_execute → Core_update_pc。
 * Fetch 讀取 32 位元機器碼；Decode 以 opcode／funct3／funct7 判斷種類；
 * Execute 依指令更新暫存器、記憶體或 new_pc；最後提交 current_pc。
 *
 * 核心原則：所有地址與暫存器均為 32 位元；x0 永遠維持 0；
 * 預設 PC 加 4，分支與跳躍可覆蓋；記憶體依小端序排列。
 * 此版本集中處理立即數符號延伸，避免對有號右移與位元欄位符號性的依賴。
 */
#include "core.h"

#include "inst.h"
#include "tick.h"
#include "arch.h"
#include "mem_map.h"
#include "common.h"

#include <stddef.h>
#include <assert.h>
#include <stdbool.h>

/*
 * 標頭用途：core.h 為核心結構與公開介面；inst.h 提供指令欄位及列舉；
 * tick.h 提供每週期回呼；arch.h 定義 32 位元型別與架構狀態；
 * mem_map.h 提供 MMIO 存取；common.h 提供 container_of 等巨集。
 * stdbool.h 提供 bool／true／false。
 */

/* 將 width 位的無號立即數擴展為 RV32 位元圖樣（width 範圍 1～31）。
 * 全程使用無號運算：最高位為 1 時，減去 2^width，得到二補數結果。
 */
static reg_t sign_extend(reg_t value, unsigned width) {
    const reg_t sign = (reg_t)1u << (width - 1u);
    const reg_t mask = ((reg_t)1u << width) - 1u;
    value &= mask;
    return (value ^ sign) - sign;
}

// ISS Fetch stage
static inst_fields_t Core_fetch(Core *self) {
    // PC 指向當前指令。經由記憶體映射讀四個連續位元組。
    byte_t inst_in_bytes[4] = {};
    MemoryMap_generic_load(&self->mem_map, self->arch_state.current_pc, 4, inst_in_bytes);
    // RISC-V 使用小端序：地址最低的 byte 放在指令 bits[7:0]，
    // 後續三個 byte 依次左移 8、16、24 位元再組合成 32 位元。
    inst_fields_t ret = {};
    ret.raw |= (reg_t)inst_in_bytes[0];
    ret.raw |= (reg_t)inst_in_bytes[1] << 8;
    ret.raw |= (reg_t)inst_in_bytes[2] << 16;
    ret.raw |= (reg_t)inst_in_bytes[3] << 24;
    return ret;
}

/*
 * Decode 的輸出是 inst_enum_t，不會在此階段改動暫存器或記憶體。
 * 先判斷 bits[6:0] 的 opcode；同一 opcode 有多種指令時，再檢查
 * bits[14:12] 的 funct3 與 bits[31:25] 的 funct7。
 * 若沒有符合 Lab 1 的 37 種合法編碼，保持 inst_invalid。
 */
// ISS decode stage
static inst_enum_t Core_decode(Core *self, inst_fields_t inst_fields) {
    (void)self; // Decode 只使用機器碼；此參數保留介面形式並避免未使用警告。
    inst_enum_t ret = inst_invalid;

    const reg_t opcode = inst_fields.R_TYPE.opcode;

    const reg_t funct3 = inst_fields.R_TYPE.func3;
    const reg_t funct7 = inst_fields.R_TYPE.func7;
    // 指令群組：OP 10、OP_IMM 9、LOAD 5、STORE 3、BRANCH 6，
    // JAL／JALR／AUIPC／LUI 各 1，共 37 種。
    switch (opcode) {
    case OP: { // R-type：來源 rs1、rs2；ADD/SUB 與 SRL/SRA 需 funct7 區分。
        if (funct3 == ADD_SUB_FUNC3) {
            if (funct7 == 0) ret = inst_add;
            if (funct7 == 0x20) ret = inst_sub;
        } else if (funct7 == 0) {
            switch (funct3) {
            case SLL_FUNC3: ret = inst_sll; break;
            case SLT_FUNC3: ret = inst_slt; break;
            case SLTU_FUNC3: ret = inst_sltu; break;
            case XOR_FUNC3: ret = inst_xor; break;
            case SRL_SRA_FUNC3: ret = inst_srl; break;
            case OR_FUNC3: ret = inst_or; break;
            case AND_FUNC3: ret = inst_and; break;
            }
        } else if (funct3 == SRL_SRA_FUNC3 && funct7 == 0x20) {
            ret = inst_sra;
        }
        break;
    }
    case OP_IMM: { // I-type：來源 rs1 及帶符號立即數；位移量取低五位。
        switch (funct3) {
        case ADD_SUB_FUNC3: ret = inst_addi; break;
        case SLT_FUNC3: ret = inst_slti; break;
        case SLTU_FUNC3: ret = inst_sltiu; break;
        case XOR_FUNC3: ret = inst_xori; break;
        case OR_FUNC3: ret = inst_ori; break;
        case AND_FUNC3: ret = inst_andi; break;
        case SLL_FUNC3: if (funct7 == 0) ret = inst_slli; break;
        case SRL_SRA_FUNC3:
            if (funct7 == 0) ret = inst_srli;
            if (funct7 == 0x20) ret = inst_srai;
            break;
        }
        break;
    }
    case LOAD: { // 依 funct3 區分 8／16／32 位元及是否做符號延伸。
        switch (funct3) {
        case LB_FUNC3: ret = inst_lb; break;
        case LH_FUNC3: ret = inst_lh; break;
        case LW_FUNC3: ret = inst_lw; break;
        case LBU_FUNC3: ret = inst_lbu; break;
        case LHU_FUNC3: ret = inst_lhu; break;
        }
        break;
    }
    case STORE: { // SB／SH／SW 分別寫入 1／2／4 個位元組。
        switch (funct3) {
        case SB_FUNC3: ret = inst_sb; break;
        case SH_FUNC3: ret = inst_sh; break;
        case SW_FUNC3: ret = inst_sw; break;
        }
        break;
    }
    case BRANCH: { // BEQ/BNE、signed BLT/BGE、unsigned BLTU/BGEU。
        switch (funct3) {
        case BEQ_FUNC3: ret = inst_beq; break;
        case BNE_FUNC3: ret = inst_bne; break;
        case BLT_FUNC3: ret = inst_blt; break;
        case BGE_FUNC3: ret = inst_bge; break;
        case BLTU_FUNC3: ret = inst_bltu; break;
        case BGEU_FUNC3: ret = inst_bgeu; break;
        }
        break;
    }
    case JAL: { // 直接跳躍並將原 PC+4 寫入 rd。
        ret = inst_jal;
        break;
    }
    case JALR: { // 間接跳躍；合法 RV32I JALR 的 funct3 必須為 000。
        if (funct3 == 0) ret = inst_jalr;
        break;
    }
    case AUIPC: { // rd ← 原 PC + 高 20 位立即數左移 12 位。
        ret = inst_auipc;
        break;
    }
    case LUI: { // rd ← 高 20 位立即數左移 12 位。
        ret = inst_lui;
        break;
    }
    }

    return ret;
}

/*
 * Execute 讀取舊架構狀態，計算結果並決定新的 PC。對所有寫 rd 的指令，
 * 最後統一寫入，確保 rs1 與 rd 相同時仍使用原本的 rs1 值。
 * 加減以 uint32_t 的模 2^32 運算自然實現 RV32I 溢位環繞。
 */
// ISS execute and commit stage (two-in-one)
static void Core_execute(Core *self, inst_fields_t inst_fields, inst_enum_t inst_enum) {
    // 預設下一個 PC；分支與跳躍可覆蓋。
    self->new_pc = self->arch_state.current_pc + 4;

    // raw 是原始 32 位元機器碼；抽取 rd、rs1、rs2 的 5 位元索引。
    // 例如 rs1=5 表示要讀 gpr[5]，不是把數值 5 當成運算元。
    const uint32_t raw = inst_fields.raw;
    const unsigned rd = (raw >> 7) & 31u;
    const unsigned rs1 = (raw >> 15) & 31u;
    const unsigned rs2 = (raw >> 20) & 31u;
    // 先讀取來源暫存器：JALR 的 rd==rs1 時尤為重要。
    const reg_t a = self->arch_state.gpr[rs1];
    const reg_t b = self->arch_state.gpr[rs2];
    // RV32I 移位只使用位移來源的低 5 位，範圍為 0～31。
    const unsigned shift = b & 31u;
    // 從原始機器碼重組各型立即數，先組位元再做 RV32 符號延伸。
    // 保持 reg_t 的 32 位元圖樣，與無號位址運算相加時自然環繞。
    const reg_t imm_i = sign_extend(raw >> 20, 12);
    const reg_t imm_s = sign_extend(((raw >> 25) << 5) |
                                     ((raw >> 7) & 0x1fu), 12);
    const reg_t imm_b = sign_extend(((raw >> 31) << 12) |
                                     (((raw >> 7) & 1u) << 11) |
                                     (((raw >> 25) & 0x3fu) << 5) |
                                     (((raw >> 8) & 0xfu) << 1), 13);
    const reg_t imm_j = sign_extend(((raw >> 31) << 20) |
                                     (((raw >> 12) & 0xffu) << 12) |
                                     (((raw >> 20) & 1u) << 11) |
                                     (((raw >> 21) & 0x3ffu) << 1), 21);
    // result 在最後統一寫回 rd；STORE/BRANCH/invalid 不寫 rd。
    // bytes 為 LOAD/STORE 的小端序緩衝區；length 為存取位元組數。
    reg_t result = 0;
    bool write_rd = true;
    byte_t bytes[4] = { 0 };
    unsigned length = 0;

    // 各列舉值的語意：signed 比較先轉成 int32_t；unsigned 直接比較 reg_t。
    switch (inst_enum) {
    case inst_add: result = a + b; break;
    case inst_sub: result = a - b; break;
    case inst_sll: result = a << shift; break;
    case inst_slt: result = (int32_t)a < (int32_t)b; break;
    case inst_sltu: result = a < b; break;
    case inst_xor: result = a ^ b; break;
    case inst_srl: result = a >> shift; break;
    // 算術右移複製符號位；邏輯右移在上方以無號 a >> shift 實作。
    case inst_sra: result = (reg_t)((int32_t)a >> shift); break;
    case inst_or: result = a | b; break;
    case inst_and: result = a & b; break;
    case inst_addi: result = a + imm_i; break;
    case inst_slti: result = (int32_t)a < (int32_t)imm_i; break;
    // SLTIU 的立即數先「符號延伸」再以 32 位元無號數比較。
    case inst_sltiu: result = a < imm_i; break;
    case inst_xori: result = a ^ imm_i; break;
    case inst_ori: result = a | imm_i; break;
    case inst_andi: result = a & imm_i; break;
    case inst_slli: result = a << (imm_i & 31u); break;
    case inst_srli: result = a >> (imm_i & 31u); break;
    case inst_srai: result = (reg_t)((int32_t)a >> (imm_i & 31u)); break;
    // LOAD：有效位址=舊 rs1 + I-type 立即數；從 MemoryMap 取 1／2／4 byte。
    // 逐 byte 依小端序重建；LB/LH 補 1 作符號延伸，LBU/LHU 保留零延伸。
    case inst_lb: case inst_lh: case inst_lw: case inst_lbu: case inst_lhu:
        length = inst_enum == inst_lb || inst_enum == inst_lbu ? 1u :
                 inst_enum == inst_lh || inst_enum == inst_lhu ? 2u : 4u;
        MemoryMap_generic_load(&self->mem_map, a + imm_i, length, bytes);
        for (unsigned i = 0; i < length; ++i) result |= (reg_t)bytes[i] << (8u * i);
        if (inst_enum == inst_lb && (result & 0x80u)) result |= 0xffffff00u;
        if (inst_enum == inst_lh && (result & 0x8000u)) result |= 0xffff0000u;
        break;
    // STORE：有效位址=舊 rs1 + S-type 立即數；rs2 的低位 byte 先存到
    // 緩衝區，再透過 MemoryMap 寫入設備，且不得更改任何目的暫存器。
    case inst_sb: case inst_sh: case inst_sw:
        length = inst_enum == inst_sb ? 1u : inst_enum == inst_sh ? 2u : 4u;
        for (unsigned i = 0; i < length; ++i) bytes[i] = (byte_t)(b >> (8u * i));
        MemoryMap_generic_store(&self->mem_map, a + imm_s, length, bytes);
        write_rd = false;
        break;
    // BRANCH：條件成立時 new_pc=原 PC + B-type offset；否則維持 PC+4。
    // BLT/BGE 採有號比較，BLTU/BGEU 採無號比較，均不寫 rd。
    case inst_beq: case inst_bne: case inst_blt: case inst_bge:
    case inst_bltu: case inst_bgeu: {
        bool taken = false;
        switch (inst_enum) {
        case inst_beq: taken = a == b; break;
        case inst_bne: taken = a != b; break;
        case inst_blt: taken = (int32_t)a < (int32_t)b; break;
        case inst_bge: taken = (int32_t)a >= (int32_t)b; break;
        case inst_bltu: taken = a < b; break;
        case inst_bgeu: taken = a >= b; break;
        default: break;
        }
        if (taken) self->new_pc = self->arch_state.current_pc + imm_b;
        write_rd = false;
        break;
    }
    // JAL：連結地址是「原 PC+4」，跳躍目標是「原 PC+J-type 偏移」。
    case inst_jal:
        result = self->new_pc;
        self->new_pc = self->arch_state.current_pc + imm_j;
        break;
    // JALR：連結地址是原 PC+4；目標=(舊 rs1+I-type 偏移)&~1，清除 bit 0。
    case inst_jalr:
        result = self->new_pc;
        // Preserve rs1 before writing rd: jalr xN, xN, imm uses the old xN.
        self->new_pc = (a + imm_i) & ~1u;
        break;
    // U-type 立即數佔 bits[31:12]，低 12 bits 自動為零。
    case inst_lui: result = raw & 0xfffff000u; break;
    case inst_auipc: result = self->arch_state.current_pc + (raw & 0xfffff000u); break;
    // 非作業要求的編碼不執行指定功能（框架既有預設 PC+4）。
    case inst_invalid: write_rd = false; break;
    }
    // x0 永遠為 0；即使一條指令以 rd=x0 為目標，也忽略寫入。
    if (write_rd && rd != 0) self->arch_state.gpr[rd] = result;
    self->arch_state.gpr[0] = 0;
}

// 每一步最後才把暫存的 new_pc 正式提交為下一條指令地址。
static void Core_update_pc(Core *self) {
    self->arch_state.current_pc = self->new_pc;
}

// Tick 回呼實作單一步驟：Fetch → Decode → Execute → 更新 PC。
DECLARE_TICK_TICK(Core) {
    Core *self_               = container_of(self, Core, super);
    inst_fields_t inst_fields = Core_fetch(self_);
    inst_enum_t inst_enum     = Core_decode(self_, inst_fields);
    Core_execute(self_, inst_fields, inst_enum);

}

### Question 3

**Why does RISC-V define conditional-set instructions? Can branch instructions alone achieve the same functionality? If yes, what is the benefit of having the additional conditional-set instructions?**

#### Your Answer

### 核心答案

條件設定（conditional-set）指令把比較結果直接寫進暫存器：條件成立寫 `1`，否則寫 `0`。本作業的 `SLT`、`SLTU`、`SLTI`、`SLTIU` 分別支援有號／無號、暫存器／立即數比較。條件分支也能透過兩條控制路徑算出相同的 0 或 1，但通常需要額外指令和標籤；條件設定則保持順序執行的 PC，結果可直接給後續指令使用。

| 指令 | 比較運算元 | 比較語意 | 結果 |
|---|---|---|---|
| `slt rd, rs1, rs2` | 兩個暫存器 | 有號小於 | 成立 `rd=1`，否則 `0` |
| `sltu rd, rs1, rs2` | 兩個暫存器 | 無號小於 | 同上 |
| `slti rd, rs1, imm` | 暫存器與符號延伸的立即數 | 有號小於 | 同上 |
| `sltiu rd, rs1, imm` | 暫存器與符號延伸的立即數 | 無號小於 | 同上 |

`Core_execute()` 對應的實作（節錄）：

```c
case inst_slt:   result = (int32_t)a < (int32_t)b; break;
case inst_sltu:  result = a < b; break;
case inst_slti:  result = (int32_t)a < (int32_t)imm_i; break;
case inst_sltiu: result = a < imm_i; break;
```

`a`、`b` 是 32 位元暫存器原值；`(int32_t)` 讓有號比較把最高位解讀為符號位。`SLTIU` **仍先符號延伸 12 位元立即數**，之後才把 32 位元位元模式拿去做無號比較。例如立即數 `-1` 經符號延伸後成為 `0xffffffff`；若 `a=0`，無號比較 `0 < 0xffffffff` 為真，因此結果是 `1`。

分支的等價寫法（示意：比較 `x1<x2`，結果放 `x3`）需安排不同控制流程：

```asm
addi x3, x0, 0
blt  x1, x2, true_case
jal  x0, done
true_case:
addi x3, x0, 1
done:
```

直接使用 `slt x3, x1, x2` 即可產生同一布林結果；實際執行成本仍取決於處理器實作與編譯器最佳化，不能宣稱所有硬體一定更快。若只是決定是否跳躍，直接使用 branch 可能最合適；若後續需要數值 0/1，conditional-set 較直接。

### Question 4

**What is the difference between `ROM` and `MainMem`? Answer this question by tracing the source code.**

#### Your Answer

### 追蹤原始碼的答案

本專案的 `ROM` 和 `MainMem` 都繼承同一個抽象記憶體介面，均可被 MemoryMap 定位並讀取；關鍵差異在 **CPU 經由記憶體映射寫入時的行為**：ROM 的 store 回呼直接拒絕修改，MainMem 的 store 回呼則將位元組寫入陣列。此處描述的是這份模擬器的軟體實作，而不是所有實體 ROM/RAM 的電路細節。

| 項目 | ROM | MainMem |
|---|---|---|
| 定義檔 | `src/rom.h` | `src/main_mem.h` |
| 映射基底 | `0x00000000` | `0x80000000` |
| 容量 | `0x1000` = 4096 bytes | `0x10000` = 65536 bytes |
| CPU load | 從 `rom[]` 複製 bytes | 從 `mem[]` 複製 bytes |
| CPU store | `Panic("ROM should not be modified!")` | 將資料寫回 `mem[]` |
| 建構時 | 將內部陣列清為 0 | 將內部陣列清為 0 |

**第一步：註冊位址。**`src/iss.c` 的 `ISS_ctor()` 建立兩個裝置，並各自註冊半開區間 `[base, base + size)`：

```c
mmap_unit_t ROM_mmap_unit = { .addr_bound = { .first = ROM_MMAP_BASE,
                                              .second = ROM_MMAP_BASE + ROM_SIZE },
                              .device_ptr = (AbstractMem *)&self_->rom_mmio };
Core_add_device(&self_->core, ROM_mmap_unit);
```

MainMem 的註冊方式相同，改用 `MAIN_MEM_MMAP_BASE`、`MAIN_MEM_SIZE` 與 `main_mem_mmio`。大小和基底來自各自的 `.h` 檔；例如 `ROM_SIZE 0x1000`，因此合法區間最後一個位址是 `0x00000fff`。

**第二步：路由存取。**`src/mem_map.c` 的 `MemoryMap_generic_load/store()` 掃描範圍，找到所屬裝置，將完整位址減去映射基底後，透過 `AbstractMem_load/store()` 派送。例如 CPU 寫入 `0x80000004`，MainMem 收到內部偏移 `4`。

**第三步：裝置決定行為。**`src/rom.c` 的關鍵程式是：

```c
DECLARE_ABSTRACT_MEM_LOAD(ROM) {
    ROM *self_ = container_of(self, ROM, super);
    for (int i = 0; i < length; i++)
        buffer[i] = self_->rom[base_addr + i];
}
DECLARE_ABSTRACT_MEM_STORE(ROM) {
    Panic("ROM should not be modified!");
}
```

`src/main_mem.c` 的 store 則有實際寫回：

```c
DECLARE_ABSTRACT_MEM_STORE(MainMem) {
    MainMem *self_ = container_of(self, MainMem, super);
    for (int i = 0; i < length; i++)
        self_->mem[base_addr + i] = ref_data[i];
}
```

程式還在各回呼中檢查裝置內存取範圍。`ISS_ctor()` 呼叫 `load_elf(elf_file_name, self_->rom_mmio.rom, ROM_SIZE, &self_->core.arch_state.current_pc)`，是**啟動時直接取得 ROM 陣列供載入器填入映像**；它並不等於程式執行期間以 store 指令寫 ROM。因此「ROM 可在初始化時載入程式」與「CPU 不可對 ROM 做一般 store」沒有矛盾。

### Question 5

**Consider `jalr xN, xN, imm`, where N is a positive number from 1 to 31. What potential problem might arise when implementing JALR in an ISS?**

#### Your Answer

### 核心答案

`jalr xN, xN, imm` 的 `rd` 與 `rs1` 指向同一個暫存器。JALR 同時要產生兩個結果：跳躍目標使用執行前的 `xN`，而連結位址 `old_pc + 4` 要寫回 `xN`。若 ISS 先把 `pc+4` 寫到 `xN`，再讀 `xN` 計算目標，就會把剛寫入的連結位址誤當舊基底，跳到錯誤位置。

| 時序 | 正確做法 | 錯誤做法 |
|---|---|---|
| 讀 rs1 | 先保存 `old_xN` | 尚未讀取 |
| 目標 | `(old_xN + sign_extend(imm)) & ~1` | `(old_pc+4 + sign_extend(imm)) & ~1` |
| 寫 rd | 最後寫入 `old_pc + 4` | 過早寫入，破壞目標運算元 |

本作業的 `Core_execute()` 先在 switch 前讀取來源值：

```c
const unsigned rd = (raw >> 7) & 31u;
const unsigned rs1 = (raw >> 15) & 31u;
const reg_t a = self->arch_state.gpr[rs1];
self->new_pc = self->arch_state.current_pc + 4;
```

JALR 分支先計算下一個 PC，統一寫回在 switch 後執行：

```c
case inst_jalr:
    result = self->new_pc;
    self->new_pc = (a + imm_i) & ~1u;
    break;
/* switch 結束後 */
if (write_rd && rd != 0) self->arch_state.gpr[rd] = result;
```

例如舊 PC 為 `0x00000100`、舊 `x5=0x00000200`、`imm=3`，執行 `jalr x5, x5, 3` 應得到新 PC `(0x200+3)&~1 = 0x202`、新 `x5=0x104`。若先寫 `x5=0x104`，錯誤目標就變成 `(0x104+3)&~1 = 0x106`。遮罩 `& ~1u` 會強制清除目標位址最低位；`imm_i` 必須先符號延伸。最後 `Core_update_pc()` 才將計算好的 `new_pc` 提交。

### Question 6 (2 pts for bonus)

**Why do the encoding formats for JAL and BRANCH instructions omit `imm[0]`?**

#### Your Answer

### 核心答案

JAL 的 J-type 偏移與 BRANCH 的 B-type 偏移，重組後最低位 `imm[0]` 都固定為 0；也就是目標相對偏移以 **2 bytes** 為最小編碼單位。既然最低位不是自由變動的資料，就沒有必要用一個機器碼欄位儲存它。把欄位留給較高位的偏移，可在固定 32 位元指令長度下涵蓋較大的相對跳躍距離。這種半字（16 位元）對齊也與可選的壓縮指令擴充相容；本實驗只執行 32 位元指令，不代表編碼中必須額外存一個恆為零的 bit。

| 編碼 | 整數偏移的位元配置 | `imm[0]` | 計算下一個 PC |
|---|---|---|---|
| B-type（BEQ 等） | `imm[12|10:5|4:1|11|0]` | 隱含 0 | `old_pc + sign_extend(imm_b)`，分支成立時 |
| J-type（JAL） | `imm[20|19:12|11|10:1|0]` | 隱含 0 | `old_pc + sign_extend(imm_j)` |

`src/core.c` 以左移 1 重組最低幾位，沒有把任何位元放在位置 0（節錄自改良版 `core_improved.c`）：

```c
const reg_t imm_b = sign_extend(((raw >> 31) << 12) |
                                 (((raw >> 7) & 1u) << 11) |
                                 (((raw >> 25) & 0x3fu) << 5) |
                                 (((raw >> 8) & 0xfu) << 1), 13);

const reg_t imm_j = sign_extend(((raw >> 31) << 20) |
                                 (((raw >> 12) & 0xffu) << 12) |
                                 (((raw >> 20) & 1u) << 11) |
                                 (((raw >> 21) & 0x3ffu) << 1), 21);
```

其中 `sign_extend(value, width)` 使用無號運算將位元圖樣擴展為 32 位元；B-type 使用 13 位、J-type 使用 21 位。B-type 的 `raw[7]` 放到 `imm[11]`；J-type 的 `raw[20]` 放到 `imm[11]`。由於最高位仍需符號延伸，正負位移都能以目前 PC 為基準跳向前或向後。JALR 不屬於這兩種立即數編碼：它採 I-type 偏移加 `rs1`，然後將**目標位址**的 bit 0 清為零，不可把兩種規則混為一談。
